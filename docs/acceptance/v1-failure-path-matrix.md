# V1 Failure-Path Matrix

This matrix records the deterministic automated evidence for the important V1 deployment failure paths. Reporting is observational: it does not authorize writes, retry deployment, or add rollback or multi-device transaction semantics.

| Failure | Detection boundary | Platform result | Write behavior | Automated evidence | Live evidence status |
| --- | --- | --- | --- | --- | --- |
| Unreachable device | Cisco IOS initial state collection / CLI | `StateCollectionError`; CLI `ERROR`, exit 2 | Approval and executor are not reached | `test_collect_device_state_wraps_connection_open_failures`; `test_deploy_branch_initial_collection_failure_prevents_approval_and_write`; `test_run_deploy_initial_collection_error_returns_two_without_report` | Pending safe read-only acceptance with a copied in-memory inventory and unused endpoint |
| Authentication failure | Cisco IOS connection open during initial collection | `StateCollectionError`; an exact configured-password value in upstream error text is replaced with `<redacted>` | Deployment is not entered | `test_collect_device_state_wraps_connection_open_failures` | Pending safe read-only acceptance with temporary settings and a disposable incorrect lab password |
| SSH host-key failure | Strict Cisco IOS connection open during initial collection | `StateCollectionError`; strict verification remains enabled | Deployment is not entered; no host-key bypass | `test_build_cisco_ios_connection`; `test_collect_device_state_wraps_connection_open_failures` | Pending safe read-only acceptance with a temporary non-matching `known_hosts` file |
| Identity mismatch | Deployment service, pre-change validation, state provider, and executor target guards | Explicit mismatch error before the protected operation | No write to an unintended target | `test_deployment_rejects_current_state_for_wrong_device`; `test_deployment_rejects_desired_state_for_wrong_device`; `test_pre_change_validation_rejects_wrong_device`; `test_collect_state_rejects_wrong_target`; `test_apply_config_rejects_wrong_target` | Not suitable for injection against a real unintended target |
| Unavailable OOB prerequisite | Branch preflight expectation construction and immediate device pre-change validation | Branch `BLOCKED`, or device `DeploymentStatus.BLOCKED` | No approval/write during failed preflight; executor not called after failed immediate validation | `test_build_pre_change_expectation_rejects_missing_oob_interface`; `test_build_pre_change_expectation_rejects_down_oob_interface`; `test_deploy_branch_blocks_when_pre_change_safety_cannot_be_built`; `test_failed_pre_change_validation_blocks_deployment` | Not suitable for destructive live injection |
| Unsupported drift | Branch-wide remediation preflight | Branch `BLOCKED`; approval status `not_requested`; evidence outcome `blocked` | Zero writes to every device, including devices with supported drift | `test_deploy_branch_does_not_write_before_branch_preflight_completes`; `test_deploy_branch_blocks_unsupported_drift`; `test_report_for_device_that_never_entered_deployment` | Automated; targeted live drift acceptance exists for supported paths, but unsupported injection is not required |
| Operator rejection | Branch approval collection | Declined device remains `declined`; a previously approved peer is `not_executed` | All approvals are collected before writes; one rejection means zero branch writes | `test_deploy_branch_collects_all_approvals_before_any_write`; `test_report_for_device_that_never_entered_deployment`; `test_run_deploy_writes_report_for_completed_workflows` | Automated; safe interactive acceptance may be repeated without device writes |
| Configuration execution failure | Device deployment service / Cisco IOS executor | `DeploymentStatus.FAILED`; attempted true, succeeded false; evidence outcome `failed` | No automatic retry and no post-change collection | `test_apply_config_rejects_failed_configuration`; `test_deployment_execution_failure_returns_failed_result`; `test_deployment_status_maps_to_final_outcome` | Not suitable for intentional invalid configuration in CML |
| Post-change collection failure | Fresh state collection after a successful executor call | `POST_CHECK_FAILED`; attempted and execution succeeded; post-change result null; evidence outcome `post_check_failed` | Configuration may already be applied; no rollback or retry is claimed | `test_post_change_state_collection_failure_does_not_mark_success`; `test_deployment_status_maps_to_final_outcome` | Deterministic automated evidence preferred; do not induce a post-write outage |
| Post-change validation failure | Complete desired-state validation of fresh post-change state | `POST_VALIDATION_FAILED`; failed post-change evidence retained; evidence outcome `post_validation_failed` | Configuration may already be applied; no second remediation or rollback | `test_post_change_validation_failure_does_not_mark_deployment_successful`; `test_deployment_status_maps_to_final_outcome` | Deterministic automated evidence preferred; do not destabilize a live device after writing |
| Already-compliant state | Branch initial validation | Branch device `SKIPPED`; approval `not_required`; evidence outcome `compliant` | No approval and no executor call | `test_deploy_branch_skips_compliant_devices`; `test_report_for_device_that_never_entered_deployment`; `test_run_deploy_writes_report_for_completed_workflows` | Live accepted through schema-v1 JSON deployment evidence with zero writes |

## Initial collection limitation

An initial connection or collection failure occurs before `BranchDeploymentResult` exists. V1 therefore returns CLI exit 2 with a clear application error and does not write a deployment JSON report for that attempt. Extending reporting to pre-result exceptions would require a new orchestration error-result subsystem and is intentionally outside this increment.

## Safe future live acceptance

The remaining safe subset uses temporary, non-repository connection inputs only: an unused endpoint for unreachable-device behavior, an intentionally incorrect disposable lab password for authentication failure, and strict host-key settings with a temporary non-matching `known_hosts` file. Secrets must not be printed, repository inventory and project trust files must not be modified, and no device configuration commands are sent.

Execution failure, post-write collection failure, post-validation failure, OOB loss, and identity mismatch against a real unintended target remain automated unless a purpose-built safe harness is approved later.
